# 视觉回归报告 — download-nexus 0.6.9

> 面板自 0.5.5 起交还壁纸（`--dc-panel: transparent`），所以「底色」不再是插件自己的常量：
> 同一份文字色在深壁纸和白壁纸上算出来的对比度不一样。这份报告按**两端**各算一次，取最差那个报。
> 全部数值由 `scripts/contrast-audit.mjs` 从 `lib/client.js` 的令牌实算，可用 `node scripts/contrast-audit.mjs` 复算。

判定口径（WCAG 2.1）：

| 用途 | 阈值 | 依据 |
| --- | --- | --- |
| 正文 / 次要文字 / 极小字 | 4.5:1 | 11–13px 属小字号正文，AA 正文门槛 |
| 状态色（成功 / 警告 / 错误）与品牌色 | 3:1 | 颜色只作辅助，旁边永远有文字，按非文本图形门槛 |
| 描边 vs 卡片 / 内层卡 | 1.35:1 | 控件边界靠描边而不是填充差 |
| 输入框 / 按钮的填充差 | 不做数值判定 | 近黑或近白的填充在 WCAG 里差不出 1.1；边界由 1px 实描边承担（已有结构断言） |

## 二、这一轮修掉的四处真实缺陷

| # | 缺陷 | 现象 | 修法 |
| --- | --- | --- | --- |
| 1 | toast 文字色借了别的令牌 | 深色下 `.dc-toast` 是 `background: var(--dc-text)` + `color: var(--dc-ink-solid)`；浅色主题里两者都是深色 → **1.13:1，字贴底看不见** | 新增成对令牌 `--dc-toast-bg / --dc-toast-ink / --dc-toast-error-bg / --dc-toast-error-ink`，深浅各定义一次；错误态不再写死 `#fff`（浅色红底上 2.96:1 → 现用 `#0b1425` 字，6.21:1） |
| 2 | 浅色极小字不够读 | `--dc-faint: #7b879c` 在白卡上 3.42:1 | 加深到 `#5f6d84` → 4.93:1 |
| 3 | 浅色描边太淡 | `--dc-line: #dbe3f0` 对卡片只有 1.22:1，控件边界几乎消失 | 加深到 `#c2cee2` → 1.50:1；`--dc-line-soft` 同步到 `#d8e0ee` |
| 4 | 输入框与卡片几乎同色 | `rgba(5,11,21,.90)` 叠在卡片上差 1.03:1，输入区看不出范围 | 深色 `--dc-field` 改实色 `#050b15`、浅色改 `#ffffff`；边界交给描边（1.97 / 1.50） |

## 三、断点与状态表达

- 容器断点统一到 **1080 / 880 / 640**（原来 1040 / 860 / 620 与验收矩阵对不上），`@supports not (container-type: inline-size)` 的媒体查询兜底同步到 880 / 640。
- 五态（就绪 / 未运行 / 未安装 / 检测失败 / 未检测）仍是「颜色 + 文字 + 圆点」三重表达，没有任何一态靠颜色单独示意。
- 断点、控件描边、toast 成对令牌都有结构断言，改样式时先红。

## 四、仍需人工截图判定的部分

1. 换壁纸后标题块与页签条是否还站得住（文字有 `text-shadow` 兜底）。
2. 窄窗 640px 下保存条换行后的按钮顺序。
3. 引擎卡错误详情展开后，卡片高度跳动是否可接受。
