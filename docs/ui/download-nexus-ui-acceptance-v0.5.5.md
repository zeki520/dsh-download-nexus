## 0. 全局度量口径（先固定，后面所有条目引用它）

### 0.1 测量方法

| 量 | 方法 | 精度要求 |
|---|---|---|
| 几何（宽高、间距、对齐、圆角） | `getBoundingClientRect()` + `getComputedStyle()`，`round(rect.height*10)/10` | ±0.5px |
| 颜色对比 | 取 `getComputedStyle` 前景色 + **实际合成后**的背景（含 alpha 逐层混合），按 WCAG 2.1 sRGB 相对亮度算 `(L1+.05)/(L2+.05)` | 保留 2 位 |
| 不透明度反解（面板层） | 同一点取两帧像素：有面板 / 无面板；令 `C_obs = a·C_panel + (1-a)·C_wall`，反解 `a` | ±0.02 |
| 层级分离 | 用 **相对亮度差 ΔL**，不用对比度比（近白区比值失真：浅色 card↔card2 比值仅 1.06，但 ΔL = 0.064，肉眼可分） | ΔL ±0.002 |
| 溢出 | `scrollWidth ≤ clientWidth+1` 且 `scrollHeight ≤ clientHeight+1`（`overflow` 非 hidden 时只查横向） | 1px |

### 0.2 壁纸样本集（对比度必须在最坏壁上过线）

| 代号 | 壁纸 | 用途 |
|---|---|---|

## 3. 最容易复发的 5 个视觉缺陷 + 检查方法

> 选取标准：① 属于「改一处 CSS 就悄悄回归」的类型；② 无自动化防线时肉眼极易漏；③ 历史上已被改回来过一次以上。

### ① 面板/卡片透明度被顺手调回「透明」

**为什么复发**：`--dc-panel`、`--dc-card` 是单点 token，任何人为了「让壁纸好看」把 `--dc-panel` 设回 `transparent` 就立刻回到本轮之前的状态，而且截图看着更「轻」。
**检查方法（3 步，缺一不可）**
1. CSS 断言：`getPropertyValue('--dc-panel')` 解析出 alpha ∈ [0.88,0.93]；`::before` 的 `display !== 'none'`。
2. 像素反解：W1 壁纸下，取面板内空白点与面板外同色点，反解 `a`，落在 [0.88,0.93]。
3. 连带断言：把卡片 alpha 与面板 alpha 一起打印，确认 `L(card) − L(panel) ≥ 0.008`（三级层级没被一起抹平）。
**阈值**：任一步不过 → 阻断。

### ② 只在默认壁纸下测对比度（亮壁纸/白壁纸跌破 4.5）

**为什么复发**：截图默认都用深色壁纸，亮的壁纸要靠人主动换；而实现把面板交出去之后，**卡片直接压在壁纸上**，壁纸亮度直接决定 muted/faint/状态色可读性。
**实测数据（这是硬证据，不是估算）**

| 场景 | 正文 | muted | faint | red |
|---|---|---|---|---|
| 深色 + W1 深壁纸 | 12.16 | 5.88 | 5.01 | 4.78 |
| 深色 + W2 亮蓝壁纸 | 6.37 | **3.08** | **2.62** | **2.50** |
| 深色 + W3 纯白壁纸 | 5.58 | **2.70** | **2.30** | **2.19** |
| 浅色 + 白 | 16.30 | 6.15 | **3.63** | 6.47 |

补充推算：即使卡片 alpha 提到需求上限 0.93，在纯白壁纸上 muted 也只有 **4.35**，仍差一点点；要到 alpha ≈ **0.95** 或把 muted 提亮才够 4.5。**这条说明「按需求写 0.88–0.93」并不自动满足 AA**，必须在清单里单独立项。
**检查方法**：固定 4 张壁纸（W1–W4）× 2 主题 = 8 组，自动跑「所有文字节点 vs 其实际合成背景」的对比度扫描，输出 <4.5 的节点清单。

### ③ 状态只靠颜色 / 两态同色

**为什么复发**：徽标颜色写在 `STATE_META` 里，调色时常把「未安装」和「未检测」都归到灰，或为了好看把琥珀改成灰蓝，文字还在但语义丢了。
**检查方法**：断言 5 个状态节点满足 —— `textContent.trim()` 长度 ∈ [2,6]、五态文字集合大小 == 5、每态 `aria-label` 非空；再人工确认两两不以「仅颜色不同」区分（未安装灰 / 未检测灰 = 唯一允许同色的组合，且必须靠文字区分，记 ⚠）。

### ④ 同一行控件不等高（历史上是 4px 错位）

**为什么复发**：输入框 36px、按钮 32px 是两套 token，`.dc-input-row` 靠 flex 居中「看起来还行」，只有在放大截图或加边框时才暴露。
**检查方法**：对每个 `display:flex` 的行容器，取所有可见子元素的 `rect.height`，断言 `max − min ≤ 1`。重点行：默认目录行、代理端口行、每组传输参数行、检测按钮行。

### ⑤ 排版 token 漂移（10.5/11px 字号、7/9/11/14px 间距）

**为什么复发**：单文件 CSS，微调时不查阶梯，「差 1px 更好看」累积成 51 处非标值；需求要求辅助 12px、模块标题 15–16px，实现已是 11/13。
**检查方法**：CSS 文本正则统计 `padding|margin|gap` 数值与 `font-size` 数值，对照白名单：
- 间距白名单 `{4,6,8,10,12,16,20,24,32}`，越界值必须附注释说明且 ≤0 处；
- 字号白名单 `{12,13,14,15,16,20}` + 允许 `18`（页面标题），越界值（10.5/11/11.5/9/7）**必须为 0**；
- 圆角白名单 `{8,10,14,999}` + `50%`，越界值（7/9/6/12）必须为 0。
当前违规计数：间距 **17**、字号 **32**（12+10+7+1+1+1 处）、圆角 **5**。

## 4. 验收输出格式（交付时按这个填）

```
[Tab] 条目ID | 判定(✔/✘/⚠) | 实测值 | 截图帧ID | 备注
```
- 一个条目一行，**实测值必须带数字**（如 `36px vs 32px`、`3.08:1`），不接受「已调整」「看起来正常」。
